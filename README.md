# 赛道雷达

> 给一个 AI 细分赛道，联网调研 5 个产品，产出一张**每个数字都能点回源头**的对比表——查不到就明说查不到。

**在线演示**：https://`<你的用户名>`.github.io/track-radar/ （在 Settings → Pages 里把 Source 设为 `/docs` 后生效）

---

## 它解决什么问题

做赛道速览时，真正难的不是"搜不到产品"，而是两件事：

1. **搜到的一堆东西能不能放在一起比**——A 是 `$20/月`，B 是"免费版 + 按量"，C 是"联系销售"，塞进同一张表需要判断和归一；
2. **哪些话能信**——官网自吹"业界第一"不能当事实，第三方实测才算。

所以这个工具不生成"一份看起来专业的报告"。它生成**一张带来源和置信度的表，外加一份缺口清单**，把不能信的地方直接摊在明面上。

## 三条不变量

这个产品的价值就是这三条。它们写在**代码里**，不是写在 prompt 里——prompt 拦不住。

| # | 不变量 | 做法 |
|---|---|---|
| 1 | **编造率为 0** | AI 每给出一个 `source_url`，代码都拿去和本次检索**真实返回过的 URL 集合**比对。对不上 → 判定为编造，清空该值、降级为「未获取」，并把原始声称留档 |
| 2 | **推导字段不能比它的依据更可信** | 「起步月费」是从「起步价原文」换算来的，两者**必须同源**；拿不到原文时月费同步降级。否则读者会看到图表画着 `$19`、表格写着「未获取」 |
| 3 | **「未获取」是正常输出** | 查不到就标未获取并进缺口清单，**不允许用常识补全**。数值含多个数字（如"$69 月付 / $59 年付"）时拒绝猜测 |

`npm test` 有 14 条断言盯着这三条，测试数据全部取自真实调研输出。

## 一次调研怎么跑

```
选赛道 → 确认产品名单 → 逐个产品：联网抓取 → 归一字段 → 来源校验 → 渲染
                                        ↑ 两阶段，不合并
```

**为什么是两阶段**：实测发现 `web_search` 工具与结构化输出无法在同一次调用里共存——模型会改写 Markdown 而不是受约束的 JSON。拆开之后反而更好：阶段一产出的 URL 清单，正好成为阶段二做来源校验的基准。

## 已知边界

这个项目**没有解决**的问题，写在最显眼的地方：

- **来源可验证 ≠ 内容正确。** 一格可以引用一个真实页面，却填进一段答非所问的页面碎片（实测：某产品的「部署方式」被抓成了帮助文档的导航句）。URL 校验拦不住这个。
- **来源可验证 ≠ 来源可信。** 广告落地页、聚合站、目录站都能通过校验。实测中某产品 6 个字段引用同一条搜索广告落地页。
- **没有任何线上验证。** 没有真实用户、没有埋点、没有 A/B。所有可用性判断都来自小规模离线核对。
- **慢。** 5 个产品约 5–7 分钟（并发 3）。这是联网抓取的真实成本，没有隐藏。

## 跑起来

```bash
npm install
npm start                       # → http://localhost:5178   （需要能调用 Claude API）
npm test                        # 三条不变量的断言
npm run build:demo              # 生成单文件演示版
```

**单文件演示版**：`npm run build:demo` 会把 CSS、JS 和**真实调研报告**一起烤进 `track-radar-demo.html`。双击即开，无后端、无密钥、无 CDN、离线可用。演示版里改数据是真的写进浏览器 localStorage，同一字段改满 2 次会当场升级为「高频错误点」——自进化钩子不是截图。

## 结构

```
lib/schema.mjs     字段定义 + 三条不变量（coerceProduct 是核心）
lib/research.mjs   两阶段流水线：联网抓取 → 归一
lib/store.mjs      校正记录沉淀（CSV）
server.mjs         HTTP + NDJSON 流式进度
public/            前端（手写 SVG 图表，无图表库）
reports/           真实调研报告存档（测试与演示的数据源）
test/invariants.mjs
build-demo.mjs     单文件打包
```

## 评测状态

按 AIPM 流程，评测设计已完成（45 条样本的分布、7 维链路诊断 rubric、8 项端到端 rubric，评测单元 = 字段槽位），但——

**评测本身一次都还没跑过。** 因此这里不出现任何准确率、满意度、效率提升的数字。已量化的只有一条：**来源校验在 4 轮实跑中共拦截 5 个编造字段**。
